# Trin — native layout Herdr

Постоянные Projects, Agents со статистикой, плоские вкладки, Files/Changes справа
и раскрываемые карточки подписок. Это нативные GPUI-моды, не HTML-макеты.

## Состав

- `layouts/trin.json` — окно, sidebar, вкладки, workspace и status/controller.
- `mods/trin-projects` — постоянный реестр; закрытие последней сессии не удаляет
  проект. Папка выбирается явно, новая вкладка запускается из корня проекта.
- `mods/trin-tabs`, `trin-tab-menu` — вкладки, оконные кнопки и меню.
- `mods/trin-agents` — основные сессии, модель, усилие, контекст, задачи и время.
- `mods/trin-brand` — шапка Deliva. Фирменный знак не объявлен MIT-ассетом:
  см. `BRAND-ASSET.md`. Право распространения с layout подтверждено владельцем.
- `mods/trin-quotas` — готовый JSON сервиса, без provider credentials.
- `keys.json` — только `layout:trin`, объединять с личными keys.

В layout `trin`: ⌘T создаёт сессию `opencode --auto`, ⇧⌘T — обычный терминал
без агента. Оба запускаются в корне выбранного проекта на его машине, включая
первую сессию пустого проекта. `--auto` сохраняет явно запрещённые permissions.

Вкладки показывают только заголовок и крестик, без логотипа программы, статуса
и zoom-суффикса. Справа от списка — OpenCode + ⌘T и терминал + ⇧⌘T вместо плюса.
Новые сессии (включая shell и явно выбранного агента) добавляются в конец по
подтверждённому ID. Drag с порогом 5px показывает ghost и сдвиг соседей за 140ms;
ширины фиксируются с нажатия, чтобы смена title при загрузке не отменяла жест.
Смена проекта/списка/ширины окна отменяет перенос; автопрокрутки у края пока нет.

Старый `trin-spaces` сохранён для rollback/regression tests, но в layout не включён.
Пустые каталоги модов, исследования, скриншоты, generated types и история макетов
в публичный набор не входят. Шесть активных модов включены; `trin-tab-menu`
вызывается другими модами, а не отдельным блоком окна.

## Установка

Нужен установленный Herdr с GPUI API поколения клона `0.1.11` (проверяйте точные
типы своей версии), curl, Python 3.9+ для remote directories/статистики Agents.
Установщик запускается из корня монорепы:

```sh
python3 scripts/install-layout.py --config-dir "$HOME/.config/herdr-app"
herdr-app do layout.switch '{"name":"trin"}'
```

Существующие имена не перезаписываются. Установщик копирует моды/layout, объединяет
только новую секцию keys и устанавливает реальные assets (`trin-brand`,
`trin-projects`, `trin-providers`). Встроенные моды Herdr не копируются и не меняются.
Это fresh-install инструмент, не updater. Сначала проверяйте в отдельной config
директории. Откат окна: `ctrl-alt-shift-escape`.

В разработке можно связать моды/layout с этим checkout symlink-ами; изображения
из `assets/` устанавливаются обычными файлами. Watcher может не увидеть изменения
внешней цели ссылки: уведомляйте ссылку `touch -h`, не заменяйте её.

## Подписки и настройка адреса

По умолчанию блок высотой 180px вмещает пять широких строк, включая OpenCode Go.
Чтобы изменить высоту, потяните границу над подписками вверх или вниз, как
границу между Projects и Agents. Herdr запоминает высоту; сворачивание и
раскрытие боковой панели её не меняет. При нехватке места (в том числе в
узком rail) список прокручивается. Основное окно Go —
5 часов, затем неделя/месяц при отсутствии 5-часового окна. Учёт по ценам API
сохраняется в подробностях каждого окна.

Для Google «Подписки» берут тот же однотонный SVG (векторный значок)
`mods/trin-agents/model-google.svg`, что и «Агенты» для Gemini и Gemma.
Буква вместо логотипа используется только для неизвестных поставщиков.

Чтобы поменять порядок, перетащите строку мышью в самой левой панели
«Подписки». Синяя линия показывает, куда встанет строка: перед соседней или
после неё. Обычный щелчок по-прежнему открывает подробности. Порядок сохраняется
в настройках Herdr на этом компьютере; новые подписки появляются внизу.
Если нужная строка за пределами видимой области, прокрутите список колесом.

Default: `http://127.0.0.1:8098/v1/quotas` от корневого Compose. Запрос выполняется
на компьютере интерфейса, не на машине выбранного проекта. Для своего сервиса:

```json
{
  "id": "quotas", "type": "block",
  "content": { "mod": "trin-quotas", "props": { "endpoint": "https://quota.example.com/v1/quotas" } },
  "size": { "px": 180 }
}
```

Это пример замены **только блока quotas** в установленном layout, не всего дерева.
Альтернатива — `QUOTA_URL` в `mods/trin-quotas/transport.js`. Приватные overrides
не коммитить: держите их в отдельном установленном layout/личном config.
Без правок исходников: `herdr-app do trin-quotas.endpoint--<URL-encoded-URL>`
записывает личный endpoint через штатный shared API (`trin.quotas.endpoint`).
URL кодировать `encodeURIComponent` целиком; пример результата:
`herdr-app do trin-quotas.endpoint--https%3A%2F%2Fquota.example.com%2Fv1%2Fquotas`.
`herdr-app do trin-quotas.reset-endpoint` удаляет override, возвращая props/default.
Приоритет: shared override → props.endpoint → QUOTA_URL. Смена адреса очищает
старый кеш и игнорирует поздний ответ прежнего сервиса; токены URL запрещены.
Транспорт принимает точный local default или HTTPS DNS/IPv4 URL `/v1/quotas`
без userinfo/query/fragment. IPv6 URL и произвольные HTTP-порты не поддержаны.
Bearer в текущем UI-транспорте не реализован: для remote сервиса требуется
защищённый частный доступ/reverse proxy; не открытый интернет.

JSON-контракт и синтетический пример: [../../docs/quota-api.md](../../docs/quota-api.md),
`tests/fixtures/quota-v1.json`. Обязательны schema v1, generated_at, subscriptions;
ID уникальны; `null` не равно нулю. Неизвестные тарифы/аккаунты не угадываются.
Email появится только при явном разрешении backend `publish_account_email=true`.

Один GET сразу и раз в 60с, без параллельных запросов; connect timeout 5с, общий
15с, ответ ≤1MiB, без redirects/curlrc. HTTPS проверяет сертификат, HTTP только
на точный loopback endpoint; loopback не проходит через proxy. SSE-контракт квот
не подтверждён, поэтому polling оставлен явно. Кеш в памяти; сбой сохраняет
last-good с предупреждением. Даты карточек в МСК (UTC+3), не timezone компьютера.

## Проекты и сессии

### Синхронизация пространств и оформление списка сессий

Действующая реализация не меняет квоты или API-учёт:

- «Сессии» выбирают иконку по семейству модели, независимо от поставщика: GPT —
  OpenAI, Claude — Anthropic, Gemini/Gemma — Google, Inkling — Thinking Machines,
  Kimi — Kimi. Если семейство неизвестно, остаётся значок или первая буква
  поставщика. Подсказка показывает исходные идентификаторы поставщика и модели.
  Заголовок «Сессии» виден в широкой панели; групп и меню сортировки нет.
  Строки можно перетаскивать в широкой и узкой панели, цветная линия показывает
  вставку выше или ниже. Порядок хранится локально независимо от вкладок;
  после первой перестановки новые сессии идут в конец. Прежние закрепления
  используются как начальный порядок, после чего все строки можно свободно
  перемещать. Короткий щелчок
  по сессии с вкладкой переводит фокус в неё.
  Непросмотренный результат отмечен точкой и лёгким синим фоном всей строки
  в широкой панели. После просмотра фон исчезает.
  Дочерние терминалы Herdr не показываются отдельными строками,
  даже если были добавлены во вкладки. Счётчик на значке приложения —
  число уникальных основных сессий, в которых нужно действие или не просмотрен
  результат. Требуется Herdr с API (программным интерфейсом) `setBadge`.
- «Новая сессия» / ⌘T запускает `opencode --auto` в корне выбранного проекта
  на его машине. `--auto` автоматически разрешает действия, кроме явно запрещённых
  permissions. ⇧⌘T открывает обычный терминал; другие агенты доступны в меню.
  Новые вкладки добавляются в конец по подтверждённому ID.
- `trin-projects.enable-native-spaces` включает opt-in Projects→Spaces:
  фоновые shell Spaces (`focus:false`), имена и порядок, без запуска OpenCode.
  Требуется поддержка `space.new {focus:false}`. Согласование событийное, только
  на ready-машинах, по одной команде; неизвестные результаты не дублируют создание.
  После закрытия последней вкладки mirror восстанавливает shell. Удаление проекта
  и всех сессий Space требует отдельного подтверждения. `disable-native-spaces`
  останавливает согласование, но не удаляет созданные Spaces. Режим работает,
  пока открыт desktop layout; мобильный клиент должен использовать тот же core.
- Проекты перетаскиваются внутри машины в wide/rail с линией before/after.
  Вкладки показывают title и крестик; drag имеет ghost и анимацию соседей,
  фиксирует ширины при нажатии, отменяется при смене контекста. Автопрокрутки
  у края нет. Кнопки OpenCode и терминала остаются вне прокручиваемого списка.

Для включения: `herdr-app do trin-projects.enable-native-spaces`; для выключения:
`herdr-app do trin-projects.disable-native-spaces`. Уже сохранённое включение
продолжает действовать после обновления. Это минимум одна сессия на проект,
не дополнительный shell рядом с каждым агентом. Имена/порядок идут Projects→Spaces,
не в обе стороны; видимость в мобильном клиенте требует подключения к тому же core.
Удаление через «Удалить проект и Space…» закрывает все его сессии после отдельного
подтверждения, но сохраняет директорию. Notification Center не меняется.

Projects хранит реестр через штатный shared API, не исходники. Публичный
`migration.js` пустой: нет чужих машин/путей/ID. Существующие native Spaces
принимаются с их собственными данными; уже сохранённые проекты не перезаписываются.
При выключенном mirror форма сама не создаёт сессии; при включённом новый проект
получает фоновый shell, о чём форма предупреждает. Remote directory
browser требует POSIX/Python 3, работает read-only через Herdr exec; Windows SSH
не поддерживается. Смена проекта не перемещает cwd уже работающих процессов.

«Сессии» показывают терминалы Herdr со статусом и работающие основные сессии
фоновой службы OpenCode V2, даже если их запустили без окна Herdr. Подписка
работает отдельно на каждой подключённой машине, в том числе без вкладок
OpenCode. Сессии из того же процесса фоновой службы сопоставляются по их
идентификатору; при доступной привязке к терминалу остаётся строка вкладки.
Фоновые строки тоже можно перемещать, но щелчок не открывает вкладку. Они
исчезают после окончания работы; вкладки, терминалы и проекты автоматически
не создаются. Отдельные экземпляры
OpenCode (`--standalone`, другая база) не обнаруживаются.

Сессии с родительским идентификатором и архивные сессии исключены. Для
проверок в общей базе используйте `opencode run --archived`; не добавляйте
этот флаг при продолжении настоящей сессии через `opencode run -s <ID>` или
для изолированного стенда со своим `XDG_DATA_HOME` (каталогом данных) / Docker.

Источники: события Herdr и OpenCode; на каждой машине используется локальная
регистрация `$XDG_STATE_HOME/opencode/service.json` (по умолчанию
`~/.local/state/opencode/service.json`). Секреты регистрации и тексты сообщений
из машины не передаются. Используется SSE (поток серверных событий) с первым
снимком после подписки. Одна подписка на машину, при смене списка целей старая
ограниченно доживает до завершения. Из-за буферизации `exec` (вызова процесса)
соединение обновляется примерно раз в 18 секунд, с контрольным снимком при
переподключении, а не постоянным опросом. Без вкладок читаются только события
жизненного цикла, переименования, смены модели и архивации; пачки событий
объединяются за 0,2 секунды (до 2 секунд для расширенной статистики).
Проверка активных сессий ограничена 128 записями, уточнение их данных — шестью
параллельными чтениями с бюджетом 3 секунды. При ошибках есть задержка между
попытками; секундное обновление на экране нужно только для локальных часов.

## Проверки

Из корня:

```sh
node --test layout/trin/tests/*.test.mjs
python3 -B -m unittest discover -s layout/trin/tests -p 'test_*.py'
herdr-app check "$HOME/.config/herdr-app/mods/trin-quotas"
```

`check` нужен для каждого установленного изменённого мода. Он не заменяет GUI:
проверяйте маленькое окно, длинные названия, rail, темы, Files/Changes, клики и
reconnect. `tests/live-projects.py` — отдельный opt-in smoke с созданием shells;
не запускать автоматически. Native form/detail checks используют временные
пакеты и не доказывают pointer/keyboard поведение.
